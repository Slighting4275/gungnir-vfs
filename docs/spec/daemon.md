# Daemon structure (src/daemon-rust)

How the daemon is put together; read before changing its start-up, its services, its test hooks or the protocol numbers.

- **Daemon start lives in the library:** `main.rs` only parses arguments, reads the live-upgrade handoff once (`ipc::Handoff::take`, first thing, single-threaded) and binds or adopts the socket; `daemon::run` owns every later phase in its order (store lock and store, health, file-op engine and its sandbox rings, services and router, sandbox, temp ledger, serving) and the rollback of a refused start. The sandbox is a seam (`daemon::Sandbox`: seccomp in the daemon, a recording fake in tests), so start order and refusal rollback are tested in process (`daemon::tests`). Both lock files (socket and store) are `lockfile::LockFile`: regular file of ours, no symlink, exclusive `flock`, adopted across a live upgrade without reopening.
- **Test hooks are read once:** every `GUNGNIR_TEST_*` hook of the daemon is parsed by `hooks::Hooks::from_env` at start (only in `test-hooks` builds; others only warn that a set one is ignored) and passed into each part's configuration (`OpsConfig::with_hooks`, `SvcConfig::daemon`, `seccomp::apply_sandbox_with`, `ipc::perform_live_upgrade`, the drain bound). No other daemon code reads a hook variable; a new hook goes into `Hooks`.
- **Protocol numbers live in one place per side:** `src/daemon-rust/src/proto.rs` and `src/client-zig/src/proto.zig` define every handshake value, the shared-memory layout, every slot kind, every reply status (one status space for all services) and the trash/recent schemes; service modules only re-export them. Both are tested against `protocol/wire.txt` (`cargo test` and `./zb test` fail on any value that differs, or a name either side lacks). A new kind or status goes into all three in one commit. On the client, `rpc.zig` is the one request/reply client every service module speaks through (metadata in `md.zig` is one of them); `rpc.statusError` turns every status into an error and `gioerr.zig` is the one map from those errors to `GIOErrorEnum` codes; services keep only their message text.
