# What the test suites must cover

`./check` runs all of it (AGENTS.md §4). This is what each suite has to prove, and the skip policy.

1. **Zig Test Suite** (from the repo root):
   - `./zb` and `./zb test --summary all` must pass on the installed nightly, with zero memory leaks under `std.testing.allocator`. `test` runs the unit tests and the integration test (`./zb itest`, which also runs `cargo build --release --bin gungnird`): child processes load `libgiogungnir.so` through GIO (`GIO_MODULE_DIR` = a dir containing only this module, `GIO_EXTRA_MODULES` unset) and assert the default VFS is `GungnirVfs` with `GIO_USE_VFS=gungnir` and `GLocalVfs` without it, and that `g_file_new_for_path("/")`, `g_file_new_for_uri("file:///")` and `g_file_parse_name("/")` query `standard::type` as a directory, and that the supported URI schemes contain `file` with no duplicates.
   - Daemon modes of the integration test (sockets, DBs and logs in `.build/tmp`): `daemon` starts gungnird (the `test-hooks` build in `.build/target-hooks/release`) and expects `daemon-state` 1 (hello, rings and ping done); `opt-in` (nothing at the socket) expects 2 within 1 s; `hung` (a socket that never accepts) expects 2 after the connect timeout, not sooner than 300 ms and within 3 s; `metadata` starts gungnird and, through `md.zig` (no GIO), identifies a file, sets and gets a string and a stringv, lists, unsets, and checks the clean errors, with a leak-checking allocator. Milestone 6 modes: `gio-metadata` (in process, through GIO) sets a string and a stringv, queries `metadata::*`, a single key and `standard::*` (no metadata), `set_attributes_from_info` with a set and an unset (statuses `SET`), a uint32 (`INVALID_ARGUMENT`), `query_writable_namespaces`, `query_info_async`, `enumerate_children`, 6 threads setting and querying at once, `g_file_move` (metadata follows) and `g_file_delete` (rows gone, checked over a second `md.zig` connection); `gio-cli` runs the `gio` tool (`gio set`, `-t stringv`, `-t unset`, `gio info -a metadata::*`, `gio info -w`), then stops gungnird and expects `gio info` to answer within 1 s without metadata and `gio set` to fail with "not available"; `daemon-stopped` stops gungnird under a live connection (queries fast and empty, sets `NOT_SUPPORTED`, state 2), restarts it and expects the module to reconnect; `ui-thread` makes the calls from a main-loop idle (query_info, enumerate_children, set, delete): with gungnird answering (metadata present), with gungnird `SIGSTOP`ped, and after `SIGCONT` plus the quiet period (metadata back), the worst single call logged against the 5 ms SLO and failed above 25 ms (scheduler noise on shared runners). Milestone 7 mode `hung-mount` restarts gungnird with `GUNGNIR_TEST_FAKE_HUNG_MOUNT`, waits (no GIO calls) until the pushed event makes `unhealthy-mounts` 1, then expects under that path, each within 100 ms: `query_info` (`standard::*,metadata::*`, no metadata), a set (`TIMED_OUT` from the module's cache), `enumerate_children` and `query_info_async` without metadata; next to it metadata still works; from a main-loop idle (the UI thread) the same query and set under the hung path stay within the 5 ms SLO (failed above 25 ms) and the file next to it still gets its metadata there (no quiet period); over a second `md.zig` connection identify fails with `SuspectMount` within 100 ms and the health queries by path and id say hung. Milestone 8 mode `file-ops` drives `GungnirFileOp`: copy with ALL_METADATA (content, mode, mtime, `metadata::*` follow; progress seen; `start` within 50 ms), copy without it (no rows), EXISTS/OVERWRITE, move (metadata follows), delete, delete-tree, fsync, NOT_FOUND/WOULD_RECURSE/NOT_EMPTY/INVALID_ARGUMENT/NOT_SUPPORTED (BACKUP), mid-copy cancel with `GUNGNIR_TEST_SLOW_OPS_MS` (CANCELLED within 2 s, no destination or temp left), a copy into a fake hung mount refused within 100 ms, and no daemon -> NOT_SUPPORTED within 1 s. Real FUSE hang, checked by hand in an unprivileged user+mount namespace (a `/dev/fuse` mount whose server never reads): the monitor marks it hung, the daemon does not block, `gio set` under it fails in < 10 ms; plain GIO `stat` there hangs with or without the module. `opt-in` and `hung` also check that, once unavailable, a metadata query is fast and empty and a set fails with `NOT_SUPPORTED` within 400 ms. In every mode `g_vfs_get_default()` plus the file queries above (and each metadata query) must return within 250 ms on the calling thread.
   - `nm -D --defined-only .build/zig-out/lib/libgiogungnir.so` lists exactly `g_io_module_load`, `g_io_module_query`, `g_io_module_unload`.
   - `gio-querymodules` on a dir holding a copy of the `.so` writes `libgiogungnir.so: gio-vfs` to `giomodule.cache`.
2. **Rust Test Suite** (from the repo root):
   - `cargo test --release` must exit code 0, also with `--features test-hooks` and with `GUNGNIR_NO_URING=1` (the daemon then picks the thread engine; the engine tests still run both engines). Where io_uring is unavailable the io_uring tests fail, unless `GUNGNIR_ALLOW_NO_URING=1` asks to skip them on purpose (each prints a SKIP line saying it did not run; `GUNGNIR_REQUIRE_URING=1`, set in CI, overrides that). No test skips silently. The same holds for what a machine may lack (btrfs and its snapshots, user+mount namespaces, FUSE in one, a non-root user, a readable-protected procfs file): such a test fails unless `GUNGNIR_ALLOW_MISSING=1` asks to skip it on purpose (a SKIP line again; `gungnird::testenv`). Where a tmpfs can stand in (holes, user xattrs, btime, `FS_IOC_GETFSUUID`, a tmpfs for the `/dev/shm` check), the test reruns itself on a tmpfs in a user+mount namespace instead of skipping. Skip and note lines go straight to stderr, never through `eprintln!`, which the harness hides for passing tests. The PKGBUILD's `check()` sets both opt-outs, so a package still builds where something is missing. CI runs `cargo test` with and without `--features test-hooks` (jobs `rust:test-hooks` and `rust:test`), and runs the test jobs as an unprivileged user (`tester`, through `runuser`), like gungnird itself, with `GUNGNIR_ALLOW_MISSING=1` for what its container cannot have (btrfs); every skip shows as a SKIP line in the job log. The Zig volume-monitor itest builds `/run/media` itself in its namespace where it is missing, and follows the same rule when no namespace can be made. Security tests run a real second user: `testenv::as_other_user` maps a subordinate uid (`newuidmap`, `/etc/subuid`) in a user namespace, so the process runs as another uid; run as root, it drops straight to `nobody` (CI: `rust:test-hooks` runs these two tests again as root, since a container's `newuidmap` cannot map ranges, and without the opt-out). With it, `another_user_is_refused_even_through_an_open_socket` (lifecycle; the daemon's `SO_PEERCRED` check refuses another user even through a world-writable, socket-activated socket; the probe is the test-only binary `gungnir-peer-probe`, `required-features = ["test-hooks"]`, never shipped) and `another_users_trash_under_our_name_is_never_ours` (trash_ipc; `.Trash-<uid>` and `.Trash/<uid>` planted by someone else are never listed, restored, deleted or emptied). Disk-full behaviour runs on a size-limited tmpfs (`testenv::rerun_on_small_tmpfs`): copies and cross-device moves fail with ENOSPC leaving no partial file or temp and never losing the source; the metadata store fails the write as a database error and reopens intact. The cross-device tests use a separate filesystem mounted at `.build/xdev` when there is one, else a tmpfs they mount themselves in a user+mount namespace (`unshare -rm`), and skip only where neither is possible; the delete-tree bind-mount test needs the same namespace.
   - `RUSTFLAGS="-D warnings" cargo check --release` and `cargo clippy --release --all-targets -- -D warnings` must exit code 0. `cargo test` includes `src/daemon-rust/tests/metadata_ipc.rs`, which runs the built gungnird over its real socket.
   - Formatting: `cargo fmt --all --check` and `zig fmt --check src/client-zig` must exit code 0 (CI gates both).

Reading `./zb test --summary all` output directly: Zig prints `failed command: ...` for every step that wrote to stderr, passing ones included. Only the final `Build Summary` line (and `error:` lines) say whether it passed; `./check` reports exactly that.
