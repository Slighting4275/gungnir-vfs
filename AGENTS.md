# PROJECT ARCHITECTURE & IMPLEMENTATION INVARIANTS

Project: Gungnir (gungnir-vfs). Daemon: gungnird. GIO module: libgiogungnir.so. Design principle: like Odin's spear, the I/O pipeline never hesitates, never stops mid-flight, and never misses: no call may block on broken mounts or metadata locks.

## 1. MANDATORY SYSTEMS LANGUAGE SPLIT
Autonomous agents must strictly adhere to this two-language architecture:

### A. CLIENT INTERFACE / GIO SHIM (`src/client-zig`)
- **Language / Toolchain:** **Zig master (nightly)**, auto-updated every night. Target output is `libgiogungnir.so`.
  - Run `zig version` before writing any Zig code, and code against that installed std, not against memory of older Zig releases (0.15 and earlier APIs are frequently wrong here).
  - If a nightly update breaks the build, read the installed std source to fix it: `zig env` prints `.std_dir` (e.g. `grep -rn 'pub fn addTranslateC' "$(zig env | sed -n 's/.*\.std_dir = "\(.*\)",/\1/p')"`). Never guess API names.
  - `build.zig.zon` `minimum_zig_version` records the OLDEST nightly the project is verified on: the ziglang.org master that CI downloads (it can lag the newest nightly by weeks). Zig does not enforce the field, so CI compares `zig version` against it. Raise it only when the code starts to need a newer std API, never just because a newer nightly also works.
- **Required Module Entry Points:**
  Must export standard GIO extension module symbols:
  - `pub export fn g_io_module_load(module: *c.GIOModule) void`
  - `pub export fn g_io_module_unload(module: *c.GIOModule) void`
  - `pub export fn g_io_module_query() [*c][*c]u8` (returns a `g_strdupv` copy of a NULL-terminated array; GIO frees it with `g_strfreev`, so never return static memory)
  - Must register the extension under `G_VFS_EXTENSION_POINT_NAME` (`"gio-vfs"`).
  - Export ONLY these three symbols. Check with `nm -D --defined-only .build/zig-out/lib/libgiogungnir.so`; keep `bundle_ubsan_rt = false` on every artifact.
- **GungnirVfs Type & VFS Selection (opt-in only):**
  - `g_io_module_load` registers `GungnirVfs` (subclass of `GVfs`) with `g_type_module_register_type`, passing the `GIOModule` as the `GTypeModule`, so it is a dynamic type that survives module unload/reload. Never use `g_type_register_static` in the module.
  - It then calls `g_io_extension_point_implement(G_VFS_EXTENSION_POINT_NAME, type, "gungnir", -100)`.
  - Priority MUST stay below GLib's `local` (0) and gvfs's `gvfs` (10) (verified in GLib 2.84.4 and 2.90.1). GIO picks the highest-priority active VFS, so a priority >= 0 would silently make GungnirVfs the default VFS for every GIO app once the module is installed.
  - Selection is opt-in per process: `GIO_USE_VFS=gungnir` (GIO looks the extension up by name, regardless of priority). The integration test checks both cases: with the variable it gets `GungnirVfs`, without it `GLocalVfs`.
  - Until the daemon path exists, the `GVfsClass` vfuncs `get_file_for_path`, `get_file_for_uri` and `parse_name` delegate to `g_vfs_get_local()` (transfer none: never unref it), never to `g_vfs_get_default()` (that is GungnirVfs itself and would recurse). Their results are transfer full and are returned as is. `is_active` returns TRUE.
  - Daemon connection (milestone 3): `instance_init` of the first GungnirVfs reads the socket path from the environment and starts ONE `gungnir-connect` GThread (`g_thread_try_new`), which runs the whole handshake (`ipc.zig` `connectAndPing`: non-blocking connect, hello, ring setup, one ping) within `connect_timeout_ms` (500). The GIO calling thread never touches the socket, and the vfuncs keep delegating to the local VFS whatever the outcome, so a missing or hung daemon can never block or break GIO. The read-only int property `daemon-state` reports 0 connecting, 1 connected (ping ok), 2 unavailable. `g_io_module_unload` joins that thread (bounded by the timeout) and closes the connection. Socket and ring code uses raw `std.os.linux` syscalls with explicit errno checks, and nothing waits without a deadline. Since milestone 6 this lives in `link.zig`: GIO threads share the one connection through `acquire(deadline)`/`release` (a GMutex taken with trylock up to the deadline, a futex wait while still connecting, both bounded by the caller's deadline; one request at a time). A transport failure (`DaemonAbsent` from the zero-timeout liveness poll of the control socket, `Protocol`, `RingCorrupt`) closes the connection and sets `daemon-state` to 2; the next metadata call at least 2 s later starts a fresh connector thread.
  - Metadata hooks (milestone 6, `gmeta.zig`): GLocalFile calls the default VFS's private `GVfsClass` slots `local_file_add_info`, `local_file_set_attributes`, `add_writable_namespaces`, `local_file_removed` and `local_file_moved` (GLib `glocalfileinfo.c`/`glocalfile.c`, the same hooks gvfs's GDaemonVfs uses); GungnirVfs fills them, so they only run with `GIO_USE_VFS=gungnir`. `add_info` returns at once unless the matcher asks for `metadata::*` or specific `metadata::<key>`s (`enumerate_namespace`/`enumerate_next`), then identifies the path and fetches all keys (list + get) or just the named ones, adding all of them or none. `set_attributes` handles every `metadata::*` attribute of the info: `string`, `stringv`, `INVALID` = unset, anything else `G_IO_ERROR_INVALID_ARGUMENT`; each attribute is marked `SET` or `ERROR_SETTING` (GLib turns an unmarked one into "not supported"), the first error only is reported. Error mapping: no daemon -> `NOT_SUPPORTED`, busy/ring full -> `BUSY`, deadline/suspect mount -> `TIMED_OUT`, missing file -> `NOT_FOUND`, too many keys -> `NO_SPACE`. `add_writable_namespaces` adds `metadata` (string, copy with file, keep when moved). `removed`/`moved` notify the daemon (best effort). Budgets: 200 ms for a whole query, 300 ms for a set/removed/moved, lock and connection waits included; a query that misses it just has no metadata attributes. On the UI thread (the thread dispatching the default main context, `g_main_context_is_owner(g_main_context_default())`: GTK handlers, idles, and the synchronous GIO calls made from them) every hook gets `ui_budget_ms` (3) instead, to stay within the < 5 ms client-thread SLO (§4); after any request times out, UI-thread hooks skip the daemon for `ui_quiet_ms` (1000) without waiting at all, and never queue behind a worker that has held the connection longer than `ui_budget_ms`. Worker threads (`query_info_async`, enumerators run in a GTask) keep the full budget, and any answered request ends the quiet period. So a stuck daemon (stopped, or its ring thread waiting out a hung mount for the resolver's 250 ms) costs the UI one 3 ms probe per second, and a UI-thread query then simply has no metadata. Symlinks are identified as themselves (like gvfs's path-keyed metadata). Hook temporaries use `std.heap.c_allocator`, passed explicitly.
  - Mount health (milestone 7, `health.zig`): after its ping the connector thread subscribes to mount-health events; a `gungnir-health` GThread drains them while the link is idle (futex wait on the reply ring, bounded), and calls drain them while waiting for a reply. The table (<= 64 mounts, paths <= 1024 bytes, behind a GMutex) is replaced by each complete snapshot; overflow, an incomplete snapshot or a lost connection makes it `unknown`, which defers to the daemon's own gate. `blocks(path)` is a pure lexical longest-prefix lookup, no syscall: never touch a hung path from the module. For paths on hung/gone mounts `add_info` adds no metadata, `set_attributes` fails with `TIMED_OUT` ("...reported by the gungnird mount health monitor") and removed/moved are not sent. GLocalFile's own `stat` still runs before the hooks, so a really hung mount still blocks plain GIO calls; that is GLib's, not ours. The health check comes first, before `link.budget`/`acquire`: on the UI thread too a call under a hung mount costs no wait, and failing it neither waits out `ui_budget_ms` nor starts the `ui_quiet_ms` period (it is not a timeout). The event thread holds the link only to drain the ring and records `held_since` like any holder. Read-only int property `unhealthy-mounts`.
  - File operations (milestone 8, `fileop.zig`): GIO has no hook for GLocalFile copy/move/delete (GVfsClass's private slots are metadata-only; GLocalFile's GFileIface and `g_file_copy`'s fallback are GLib's own, behind `G_IS_LOCAL_FILE` checks), so the async engine is exposed as a dynamic GObject type `GungnirFileOp` (registered in `g_io_module_load`, no new export; look it up with `g_type_from_name`). Construct-only props `operation` (1 copy, 2 move, 3 delete, 4 delete-tree, 5 fsync), `source`, `destination`, `flags` (GFileCopyFlags, no BACKUP), `timeout-ms`; action signal `start(GCancellable)` -> gboolean returns at once; `progress(gint64, gint64)` and one `finished(GError*)` are emitted on the caller's thread-default main context. Each op runs on a detached `gungnir-op` GThread with its own connection; every wait is bounded (connect 500 ms, accept 1 s, op timeout + 2 s, 45 s without events, 50 ms slices polling the GCancellable, cancel answered within 2 s). Paths that `health.blocks` are refused with `TIMED_OUT` without a connection; no daemon gives `NOT_SUPPORTED`; <= 16 live ops (else `BUSY`). The first start pins the module (class ref never dropped).
  - `get_supported_uri_schemes` returns GungnirVfs's own static, NULL-terminated class list (`{ "file", NULL }`, the same as GLocalVfs's class vfunc). Never return `g_vfs_get_supported_uri_schemes(g_vfs_get_local())`: GVfs caches the element pointers, which point into the local VFS's private scheme table (freed by `g_vfs_unregister_uri_scheme`: use-after-free), and the base class would list `resource` twice.
- **C Linkage & VTable Definitions:**
  - Link `libc` and `libgio-2.0` (mandatory; host GTK processes already link glibc).
  - Consume GLib/GIO headers exclusively through the build graph: `b.addTranslateC` on a header generated in `build.zig` (`#include <gio/gio.h>`), imported as module `c` (`const c = @import("c");`). `@cImport` no longer exists on Zig master.
  - Variadic C macros (e.g. `g_critical`, `g_warning`) cannot be translated; call the underlying function (`c.g_log`) directly.
  - Implement GObject virtual tables (`GVfsClass`, `GFileIface`) as Zig `extern struct` types containing typed function pointers matching C ABI prototypes. Untyped `*anyopaque` or `void*` casts for vtables are forbidden. Class structs embed the translated parent class (`extern struct { parent_class: c.GVfsClass }`) and `class_init` assigns typed `callconv(.c)` functions to its slots; the only pointer casts allowed are GObject's own: `class_init`'s `gpointer` class argument to the class struct, and instance upcasts such as `*GIOModule` to `*GTypeModule`.
- **Panic Prevention & C-ABI Safety:**
  - Zig's root panic handler (`pub const panic = std.debug.FullPanic(fn)` on the current master; re-check in the installed std after updates) is `noreturn` and cannot resume execution. Code paths handling external input must NEVER trigger panics.
  - Ban `@panic`, `unreachable`, and implicit slicing/arithmetic assertions on untrusted paths. Use explicit error-returning forms (`std.math.add`, bounds-checked slicing with error returns).
  - Root panic handler must safely format Zig's string slice using a precision specifier, call GLib logging, and terminate via `exit_group`. Clamp the length with `@min` BEFORE narrowing: a bare `@intCast(msg.len)` re-enters the panic handler in safe builds (losing the original message) and is UB in `ReleaseFast`/`ReleaseSmall`, where a negative `%.*s` precision makes `g_log` read past the slice:
    ```zig
    const max_panic_msg_len = 4096;
    c.g_log(null, c.G_LOG_LEVEL_CRITICAL, "gungnir panic: %.*s", @as(c_int, @intCast(@min(msg.len, max_panic_msg_len))), msg.ptr);
    std.os.linux.exit_group(1);
    ```
  - Every exported C boundary must wrap internal Zig logic in `catch` blocks and populate `GError**` using `c.g_set_error()`.
- **Memory & Allocation Scope:**
  - Pure Zig structures must explicitly take an allocator (`std.mem.Allocator`). No hidden heap allocations inside Zig code.
  - GLib internal allocations (such as `g_object_new`, `g_set_error`, or `g_strdupv`) are exempt from the Zig allocator requirement.
- **Kernel Syscalls & Non-Blocking Worker Fallback:**
  - Primary path: Direct asynchronous kernel `io_uring` queues where supported.
  - Mandatory fallback: If `io_uring_setup` fails (`EPERM`, `EACCES`, `ENOSYS`), fall back to POSIX `getdents64` and `statx(2)`.
  - Concurrency invariant: Synchronous POSIX fallback operations (`statx`, `getdents64`) block the calling thread. They MUST NEVER execute on the GTK main thread. Schedule them onto GLib worker threads via `GTask` (`g_task_run_in_thread`) so the host UI loop never stalls.

### B. BACKGROUND DAEMON & STORAGE WORKERS (`src/daemon-rust`)
- **Language:** Strictly **Rust** stable (binary `gungnird`, edition 2024).
- **Async Reactor:** Use raw `io-uring` or `monoio` (thread-per-core io_uring). Banned: `tokio-uring`.
- **IPC & Shared Memory:**
  - Low-latency data transfers must use shared-memory ring buffers (`memfd_create` + futexes) managed via `AF_UNIX` control sockets.
  - Futex operations MUST be process-shared (`FUTEX_WAIT` and `FUTEX_WAKE` without `FUTEX_PRIVATE_FLAG`).
  - **Handshake protocol v2** (`src/daemon-rust/src/ipc.rs` and `src/client-zig/src/ipc.zig` mirror each other; change both together and bump the version for any layout change):
    - Socket: `AF_UNIX` stream at `$GUNGNIR_SOCKET`, else `$XDG_RUNTIME_DIR/gungnir/gungnird.sock`, else `$HOME/.cache/gungnir/gungnird.sock` (absolute values only; never `/tmp`; must fit `sun_path`). The daemon creates the directory `0700` and refuses an existing one that is not a directory owned by its euid or is world-writable. It holds an exclusive `flock` on `<socket>.lock` for its whole life (two daemons starting at once can never unlink each other's socket), replaces a stale socket, refuses to start if another daemon answers a NON-blocking probe connect (EAGAIN, a full backlog, counts as alive), and makes the socket `0600`.
    - Peers are authenticated with `SO_PEERCRED` on both ends: the daemon serves, and the client talks to, only a peer with the same effective uid. The daemon serves at most 64 clients at once and closes further connections immediately.
    - Frames are 16 bytes, little-endian: `magic u32` (`"GNGR"`) | `version u16` | `kind u16` (1 hello, 2 ack, 3 reject) | `status u32` (0 ok, 1 bad magic, 2 bad version, 3 bad kind) | `shm_size u32`. The client sends hello. The daemon answers ack with exactly one memfd via `SCM_RIGHTS`, or reject with no fd and closes. A client that has not sent its whole hello within 2 s in total (not per read) is dropped.
    - Shared memory (266240 bytes, sealed `F_SEAL_SHRINK | F_SEAL_GROW | F_SEAL_SEAL`): header `magic, version, slot_count = 32, slot_size = 4096` (u32 each) at 0. Ring client->daemon: `head` at 64, `tail` at 128, slots at 4096. Ring daemon->client: `head` at 192, `tail` at 256, slots at 135168. Slot: `kind u32` (1 ping, 2 pong, 16-22 metadata requests, 32 metadata reply) | `len u32` (<= 4080) | `seq u64` | `payload[4080]`; only the words covering header and payload are copied, the length is validated before the payload is read. v1 (64 x 64-byte slots) is refused with `status` 2; the Zig client reports it as `error.VersionMismatch`. `head`/`tail` are free-running u32 counters, written only by producer/consumer respectively. The producer release-stores `head`, then `FUTEX_WAKE`s it, and the consumer `FUTEX_WAIT`s on `head` with a timeout. Slot bytes are read and written only with atomic 8-byte accesses (the peer may write them at any time) and validated after the copy.
    - Both sides treat the peer's memory as untrusted: check size and seals before `mmap`, validate the header, `head - tail <= slot_count` (wrapping) and `len`, and fail with an error, never a panic. The daemon answers each ping with a pong carrying the same `seq` and payload, and drops the rings when the control socket closes.
    - Metadata messages (milestone 5, `src/daemon-rust/src/md.rs` and `src/client-zig/src/md.zig` mirror each other): identify `path` (16), get (17), set (18, `string` or `stringv`), unset (19), list keys after a cursor (20, paginated with a `more` flag), removed `path` (21) and moved `src len16 | dest len16` (22) (milestone 6: GIO reports a delete/rename after it happened; new kinds, not a layout change, so still v2 and an M5 daemon answers 13). Every request gets one reply (32) with the request's `seq`: `status u32 | body` (0 ok, 1 not found, 2 busy, 3 timeout, 4 suspect mount, 5 no such file, 6 bad request, 7 key too long, 8 value too large, 9 too many keys, 10 bad UTF-8, 11 I/O, 12 database, 13 unsupported). Requests carry the identity the daemon returned from identify. Stale rows (the btime rule below) are deleted only when identify, which sees the file's current btime, finds them; a get/set/unset/list whose btime differs from the stored one never deletes anything (get and list answer not found / no keys, set and unset answer `no such file`: identify again). Limits (both sides check; the daemon is authoritative): key 1..=256 bytes, encoded value <= 3072 bytes, stringv <= 64 items, 128 keys per file, all strings UTF-8 without NUL. Payloads are parsed with bounds-checked readers and must be consumed exactly. removed: the ring thread resolves the path (resolver deadline); a file still/again there is `alive`, any error other than "no such file" answers that error and drops nothing; the DB thread then drops the metadata and hint of every identity whose `path_hint` is that path, except `alive` (reply `forgotten u32`), and except files that had more than one hard link when their hint was written (`path_hint.links`, the `stx_nlink` seen by the identify before the set): they live on under another name, so only their hint is dropped (the key is the inode, not the name; orphaned rows are harmless, lost ones are not). moved: the ring thread resolves `dest`; the DB thread drops identities hinted at `dest` other than the moved one (replaced by the rename; the same hard link rule), points the moved file's hint at `dest` if it has rows, and rewrites every hint below `src/` to below `dest/` in the same transaction (one indexed range `UPDATE` over the byte-wise range `[src/, src0)`, no `LIKE`, results kept `BLOB`; reply `rewritten u32 | forgotten u32`). Metadata itself is keyed by identity, so a rename never moves rows. Known limit: only files whose hint matches are found; a file renamed behind GIO's back keeps its old hint until its next set, and a later GIO delete of whatever then sits at the old path drops it too (unless it had several links); a link count that grew after the last set is not seen.
    - Mount health (milestone 7, `src/daemon-rust/src/health.rs`, mirrored by `health.zig`): a monitor thread polls `/proc/self/mountinfo` (`POLLPRI`, re-read retried until it works) plus an eventfd, and probes only network and FUSE mounts (`fuse*`, nfs, cifs/smb, 9p, ceph, afs, lustre, glusterfs, davfs, coda, virtiofs...) with `statfs` on sacrificial threads: one probe in flight per mount, <= 8 probes within their deadline plus <= 56 threads stuck past it (256 KiB stacks; a thread stuck in `statfs` cannot be reclaimed, so stuck ones never take the 8 slots that keep the other mounts probed), deadline 1 s, every 5 s, answers over 250 ms = slow, failures back off 1 s doubling to 60 s. States healthy/slow/hung (deadline missed, or `ETIMEDOUT`)/gone (`ENOTCONN`, `ESTALE`, `EIO`, `ENODEV`, connection errors). Hung and gone mounts are marked suspect in the M4 resolver (`Resolver::mark_suspect`, cleared on recovery or unmount; reconciled with the monitor's table before its core lock is released, so the resolver never disagrees with a state a lookup has seen and marks/clears never land out of order) and the `Gated` backend refuses paths under them without a syscall (`SuspectMount`). New kinds, still v2 (an M6 daemon answers 13): query (23, `by u8` 0 = path | 1 = `mnt_id u64`; reply `mnt_id u64 | state u8 | probed u8 | latency_us u32 | mount_point len16`), subscribe (24, reply `epoch u64`, then the current snapshot), event (33, unsolicited, `seq` 0: `epoch u64 | flags u8 (1 first, 2 last, 4 incomplete) | count u16 | (mnt_id u64 | state u8 | path len16)*`, <= 4 slots). A snapshot lists every unhealthy mount and every mount at or below one, so longest-prefix on it equals longest-prefix on the full table; it is pushed whole only while 17 slots stay free (replies never starve) and retried every 100 ms, older ones are superseded, never queued. Test hook: `GUNGNIR_TEST_FAKE_HUNG_MOUNT=<absolute dir>` adds a fake FUSE mount there whose probes never return, honoured only in builds with the cargo feature `test-hooks` (never a default feature; the Zig itest builds that gungnird into its own `.build/target-hooks`, never over the release `.build/target/release/gungnird`, and CI checks the shipped binary has no hook); otherwise it is ignored with a warning.
    - File operations (milestone 8, `ops.rs`, `ops/io.rs`, wired by `opsvc.rs`): an engine probed at startup, io_uring through the `io-uring` crate (never `tokio-uring`; one ring per worker, interruptible 50 ms waits, `AsyncCancel` on stop) or plain syscalls on threads when the probe fails (ENOSYS/EPERM under seccomp or containers) or `GUNGNIR_NO_URING=1`. Copy: `FICLONE`, else data segments (`SEEK_DATA`/`SEEK_HOLE`, sparse files stay sparse) by `copy_file_range`, else engine read/write; into an `O_EXCL` temp `.gungnir-<id>-<n>.tmp` beside the destination, then mode/timestamps (unless the TARGET_DEFAULT_* flags), xattrs best effort with ALL_METADATA, fsync, `renameat2(NOREPLACE)` (or plain rename with OVERWRITE); temp unlinked on any error. Move: rename, across devices copy + unlink (not with NO_FALLBACK_FOR_MOVE, not directories). Delete, delete-tree (fd-relative, no symlink following, refuses mount crossings, depth <= 256), fsync. Bounded: 4 workers (<= 16 threads), queue 64 (else `busy`), <= 8 ops per connection; per-op deadline (default 1 h, max 24 h), 30 s stall limit; a watchdog finishes ops whose thread is stuck in the kernel (after 250 ms grace), marks their mount suspect and replaces the thread. The M7 gate refuses paths on hung/gone mounts at once (`SuspectMount`). Metadata rows follow moves; copies duplicate them only with `G_FILE_COPY_ALL_METADATA`; deletes drop them. Kinds, still v2 (older daemons answer 13 `unsupported`): start (25, `op u8 | flags u32 | timeout_ms u32 | src len16 | dest len16`; reply `status | op_id u64`), cancel (26, `op_id u64`), progress (34, unsolicited, `op_id | bytes_done | bytes_total | files_done`, throttled to 100 ms, never using the reply reserve), done (35, reply to the start's seq: `op_id | status u32 | errno i32 | bytes | files`; statuses 14 cancelled, 15 OS error + errno, 16 would-recurse). Ops of a closed connection are cancelled. Test hook (feature `test-hooks`): `GUNGNIR_TEST_SLOW_OPS_MS`.
    - Non-blocking rule for metadata: the connection's ring thread parses and validates; identify goes through the M4 `Resolver` (its deadline bounds the wait); every database operation is handed to the single `gungnir-db` thread through a bounded queue (128; full means `busy` at once) and the ring thread never waits for it: the DB thread pushes the reply itself (a per-connection mutex serialises the two producers of the reply ring, held for one slot copy only). At most 16 requests per connection are in flight; beyond that the ring thread stops reading requests until replies drain. A job older than 500 ms when dequeued is answered `busy` without running.
- **Metadata Storage (SQLite in WAL Mode):**
  - Default database path: `$XDG_DATA_HOME/gungnir/metadata.db`, else `$HOME/.local/share/gungnir/metadata.db` (absolute values only; overridable by the first CLI argument). The directory is created `0700` and refused if it is not ours or is group/world-writable; the file is created (or tightened to) `0600`, and SQLite gives `-wal`/`-shm` the same mode.
  - Required PRAGMAs:
    `PRAGMA journal_mode = WAL; PRAGMA synchronous = NORMAL;` and `busy_timeout` 20 ms with at most 2 retries (5 ms apart), then `busy`. Never a long busy_timeout while serving: one DB thread serves every client. Opening the database (switching to WAL, creating the schema) happens before anything is served and may wait up to 5 s (busy_timeout, plus retrying the setup on an immediate `SQLITE_BUSY`), so a second opener or a backup cannot stop the daemon from starting.
  - Table schema:
    ```sql
    CREATE TABLE metadata (
      fs_uuid    TEXT    NOT NULL,
      subvol_id  INTEGER NOT NULL,
      inode_num  INTEGER NOT NULL,
      generation INTEGER NOT NULL,
      key        TEXT    NOT NULL,
      btime_sec  INTEGER NOT NULL DEFAULT 0,
      btime_nsec INTEGER NOT NULL DEFAULT 0,
      value      BLOB,
      PRIMARY KEY (fs_uuid, subvol_id, inode_num, generation, key)
    ) WITHOUT ROWID;
    ```
    `value` is the wire encoding of the value (type byte first). Last known path, a hint for later moves and GC (recorded on set from the connection's last identify of that identity; dropped with the file's last key):
    ```sql
    CREATE TABLE path_hint (
      fs_uuid TEXT NOT NULL, subvol_id INTEGER NOT NULL, inode_num INTEGER NOT NULL,
      generation INTEGER NOT NULL, path BLOB NOT NULL, updated INTEGER NOT NULL,
      PRIMARY KEY (fs_uuid, subvol_id, inode_num, generation)
    ) WITHOUT ROWID;
    CREATE INDEX path_hint_by_path ON path_hint (path); -- removed/moved look hints up by path (M6)
    ```
  - Unlink/delete path:
    - Deleted files are removed with `DELETE FROM metadata WHERE fs_uuid = ? AND subvol_id = ? AND inode_num = ?`, batched in a single transaction per event burst.
    - Do NOT add a separate index on `(fs_uuid, subvol_id, inode_num)`: the PRIMARY KEY prefix already serves deletes, and an extra index adds a write to every insert.
    - GIO deletes (milestone 6, `removed`) currently drop one identity's rows by the full key including `generation`, one transaction per notification; the batched burst path is for the future event watcher.
  - Inode Tracking & Collision Defense:
    - `generation`: Query via `ioctl(fd, FS_IOC_GETVERSION, &generation)`. If unsupported by the filesystem, set `generation = 0`. NEVER use `stx_ctime` as a key or fallback; `ctime` changes on chmod, rename, hard link, and xattr writes, causing key churn and metadata loss.
    - `btime` (staleness check, not part of the key): Record `stx_btime` when `stx_mask & STATX_BTIME` is set; otherwise store `0`. On lookup, if both the stored and current `btime` are non-zero and differ, treat the row as stale (recycled inode) and delete it.
    - `subvol_id`: Query via `statx` (`STATX_SUBVOL`, Linux 6.10+) or `BTRFS_IOC_INO_LOOKUP`; default to `0` on filesystems without subvolumes.
    - `fs_uuid` retrieval, in order:
      1. `ioctl(fd, FS_IOC_GETFSUUID, &fsuuid)` (Linux 6.8+).
      2. Parse `/proc/self/mountinfo` for the mount's `major:minor` and source device, then resolve the UUID via the matching symlink in `/dev/disk/by-uuid/`.
      3. Synthetic ID for UUID-less filesystems, formatted `synth-<first 32 hex chars of BLAKE3>` (each input length-prefixed, see `synth_fs_id`). Read `f_type` via `statfs(2)` (`statvfs` has no `f_type`). Hash inputs by filesystem class:
         - Volatile (`tmpfs`, `ramfs`): `f_type || mount_point || boot_id`, where `boot_id` is read from `/proc/sys/kernel/random/boot_id`. Contents are wiped each boot, so IDs must not survive a reboot.
         - Network (`nfs`, `nfs4`, `cifs`, `smb3`): `f_type || mount_source` (e.g. `server:/export`), so an export keeps its ID regardless of mount point.
         - Everything else (FUSE and others): `f_type || mount_source || mount_point`.
      - Hash with the `blake3` crate ONLY. Never use Rust's `DefaultHasher`/SipHash: its output is not guaranteed stable across Rust versions and would silently orphan every synthetic ID after a toolchain upgrade.
    - Resolver (milestone 4, `src/daemon-rust/src/fsid.rs`): a path is opened `O_PATH | O_NOFOLLOW` (a symlink is identified as itself) and one `statx` (`AT_STATX_DONT_SYNC`) gives `inode_num`, `subvol_id`, `btime` and `STATX_MNT_ID`. The ioctls need a readable fd, so only regular files and directories are reopened through `/proc/self/fd` (`O_RDONLY | O_NONBLOCK`); FIFOs, devices and every FUSE file are never opened and get `generation = 0` (FUSE forwards `FS_IOC_GETVERSION` to the userspace server and has no `s_uuid`). A failed reopen is returned (`EACCES`, `EMFILE`, no procfs), never turned into `generation = 0`; the one exception is `EACCES`/`EPERM` on a filesystem whose root directory (same mount id) answers `FS_IOC_GETVERSION` as unsupported, where 0 is what a readable fd gives too. On btrfs without `STATX_SUBVOL` (Linux < 6.10) `subvol_id` comes from the unprivileged `BTRFS_IOC_INO_LOOKUP` (treeid 0, objectid 256) on that readable fd, the same value `STATX_SUBVOL` reports; a btrfs symlink, FIFO or device there fails with `NoSubvol` rather than collide on subvolume 0. Unsupported ioctls (`ENOTTY`, `EINVAL`, `EOPNOTSUPP`, `ENOSYS`) mean 0/next step; any other error is returned, never turned into a different key. `fs_uuid` and `f_type` (one `statfs`, a server round trip on NFS/FUSE) are resolved once per mount and cached by mount id (an entry is dropped when its mountinfo line changes or vanishes); step 1 tries the file, then the mount's root directory (same mount id only); UUIDs are lowercase in both steps 1 and 2. Synthetic ids hash `f_type` as the 32-bit magic zero-extended to a little-endian u64. `/proc/self/mountinfo` fields are split on single spaces (an empty source is a real field). It is re-read only when a zero-timeout `poll` reports `POLLPRI`; `poll` itself clears the kernel's flag, so a failed re-read is retried on the next lookup.
    - Non-blocking rule for identity: every syscall on the target runs on a `Resolver` worker (4 started, at most 16 threads counting stuck ones, a bounded queue). The caller waits at most the deadline (250 ms): a request a worker started but did not finish returns `Timeout` and marks its mount (longest mount-point prefix, from the cached table, never a syscall on the target; asked again at the timeout if the cache was busy at dispatch) suspect for 30 s (a span that overflows `Instant` means until cleared), so later requests for it fail fast with `SuspectMount`; a request that never reached a worker returns `Busy` and blames no mount.
- **Error Propagation:**
  - Set `panic = "abort"` in release profiles.
  - All disk, network, and IPC boundaries must return typed `Result<T, E>`. No `unwrap`/`expect` outside tests.
